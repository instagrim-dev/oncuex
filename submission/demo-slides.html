Approval is not.

An event launch tool that keeps a sign-off tied to the evidence behind it — and tells you the moment that evidence moves.

OnCueX1 / 14
The problem

A checked box is not evidence.

Every launch tool can show you a task list with ticks through it. None of them can tell you whether the plan underneath still holds.

The obvious failure

Requirements are marked done while nothing current supports them. Access windows, crew calls, run of show and committed cost quietly disagree with each other.

The embarrassing one

The venue changes. Some commitments lose their support and others don't. The approval granted before the change still looks current — and nobody can say which parts are still true.

OnCueX4 / 14
The central distinction

Readiness is computed. Acceptance is recorded.

Computed

Readiness

A pure function over one snapshot. Returns missing blocked outdated supported with a named reason for each. No model in the loop.

Recorded

Acceptance

Exists only as a decision by a named project manager against one revision, one requirement set and one evidence set. The evaluator can never emit it.

A green badge can never impersonate a person.

Why it's built this way

Two counters, because an opinion is not a fact.

Recording a sign-off must not invalidate the sign-off. That single sentence drives the storage design.

CounterAdvances onDecides
eventSequenceevery event, including a sign-offaudit ordering
assessmentRevisiononly changes to assessed factswhether an approval is still current

Sign-off advances the first and leaves the second alone — so it is current the instant it is written, and still current after a reload.

Earlier versions bound decisions to the single revision and staled every approval on write. That was the first defect found in review.

What survives the change

Impact comes from declared bindings, not a diff.

Each requirement declares the fields it depends on. Each evidence record records the values it was bound to. A change walks those declarations, then closes over the prerequisite graph.

6 requirements · 6 records

Work to revisit

Loading, capacity, crew arrival, run of show, budget, fire attestation.

1 requirement · 1 record

Keep as it is

Photographer delivers 120 edited images within 10 days. Binds to no venue field. No blanket reset touches it.

Marking the photographer outdated is a defect, and a test fails if it happens.

OnCueX8 / 14
The AI boundary

Proposes, and cannot write.

Two allowlisted operations

  • extractBrief — structured brief from pasted text, every claim carrying a source span
  • draftRecovery — proposed field changes with rationale and sources

Rejected, however confident

  • a vendor confirmation no source asserts
  • attribution to someone who didn't say it
  • any change to status, readiness or budget
  • instructions embedded in uploaded material

Output lands as a proposal with author.kind = "model". Adoption is a separate human command with its own expected revision. The model has no channel to the writer.

OnCueX9 / 14
Source review

A concern is not a plan change.

Items arrive from named channels — Gmail, Slack, iMessage, Zoom, Research, Manual — each with a locator and a content digest.

Reviewing one records a disposition: concern, dismissed, deferred, clarification, resolved. The reviewed item is retained; the plan is untouched.

Concern

A judgement about a source

Recorded against the review, with a reason and who raised it.

Change

A command against the plan

Requires an expected revision, produces a new one, and requires re-assessment.

Merging these is how a comment silently becomes a commitment.

OnCueX12 / 14
Limits

What this does not do.

  • It does not decide. The model extracts and drafts; a person adopts and signs off.
  • It does not verify physical reality. It checks records, dates and internal consistency — permits, accessibility and safety stay with qualified people.
  • It does not secure multiple users. Contributor roles are simulated and labelled, and the record lives in the operator's browser.
  • It does not estimate savings. No comparison against a manual baseline has been measured.
  • It does not use real data. Every person, venue and price is fictional.

The scenario is one synthetic launch. A result on it is a result on it.
